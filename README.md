# よりみちラジオ v0.2.2

[Windows用の配布ZIPをダウンロード](https://github.com/tyatya123/yorimichi-radio-public/releases/latest)

手持ちの音楽と短いDJトークを交互に流す、個人向けのローカルアプリです。Windows PC内で動作し、ブラウザから操作します。有料API、アカウント登録、追加のPythonパッケージは必須ではありません。配布ZIPにはアプリ本体とデモ曲を含め、VOICEVOX・Ollama・LLMモデルは初回セットアップで公式配布元から取得します。

初めて使う場合は [はじめに.txt](はじめに.txt) も参照してください。今回の機能と制限は [リリースノート](RELEASE_NOTES.md) にまとめています。

## v0.2.2のセキュリティ対応

RSSの文字列処理にかかる時間、文字コードを使ったXMLのDTD禁止回避、CSPなどの応答ヘッダー、ローカルAPIの認証を改善する版です。曲IDの不正な型もSQLiteへ渡す前に拒否し、一般的な500ではなく入力エラーとして扱います。修正の統合試験・再検査の結果は [VERIFICATION.md](VERIFICATION.md) に別記し、以前の版の成功結果と区別します。

## 必要な環境

- Windows 10 / 11の64bit（x64）環境とブラウザ。動作確認にはMicrosoft Edgeを使用しています。
- Pythonの手動インストールは不要です。セットアップが公式の埋め込み版Pythonを `runtime/python` に取得します。
- 初回セットアップ用のインターネット接続。ランタイムとモデルのダウンロードには時間がかかります。
- 初回ダウンロードは合計約6GB、導入後の保存は約7GBが目安です。ダウンロード・展開中の一時領域を含め、空き容量は約12GBを目安に確保してください。取得する版やモデルによって増減します。

CPUだけでも動作する構成です。NVIDIA GPUは必須ではありません。LLMの速度とメモリ使用量はPC性能によって変わります。

## 起動

1. ZIPを、書き込みできるフォルダへすべて展開します。ZIPの中から直接起動しないでください。
2. `setup.cmd` をダブルクリックし、画面の案内に従います。Python・VOICEVOX・Ollama・ローカルLLMモデルを公式配布元から初回のみ取得します。
3. セットアップ完了後、`start.cmd` をダブルクリックします。ローカルエンジンを必要に応じて非表示で起動し、同じWindows利用者向けの認証情報を使ってブラウザでラジオ画面を開きます。初回のエンジン準備には少し時間がかかります。
4. 音楽フォルダ、またはファイル選択から曲を追加し、再生ボタンを押します。まず動作を試す場合は「デモ曲で試す」を使えます。

セットアップ完了だけではラジオは起動しません。続けて `start.cmd` を実行してください。再セットアップ時も既存の `data/settings.json` は保持します。ローカルLLMを使わない場合もアプリは動作し、設定でLLMをオフにすると定型トークを使用します。

`http://127.0.0.1:8765` を直接入力して初めて開いた場合は、起動ファイルから開き直す案内が表示されます。`start.cmd` を実行して開いてください。認証情報の付いた起動時URLや音声の署名URLは他の人へ共有しないでください。

Pythonだけを取得して軽く試す場合は `setup.cmd -PythonOnly` を実行できます。この場合はブラウザの日本語音声と定型トークを使います。後から通常の `setup.cmd` を実行してエンジンとモデルを追加できますが、既存設定を保つため、LLMは「ラジオの設定」でオンにしてください。`setup.cmd -VerifyOnly` はダウンロードや起動をせず、必要な実行ファイルとモデル情報の有無を確認します。

ブラウザは最初の再生操作を必要とします。ブラウザのタブを閉じてもローカルサーバーは動作します。終了するときは `stop.cmd` をダブルクリックします。ラジオを停止した後、このアプリが起動したと確認できるローカルエンジンも終了します。もともと起動していた別のサービスや、ほかのラジオで利用中のエンジンは停止しません。PowerShellからは以下でも終了できます。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\stop.ps1
```

ポート8765を別のアプリが使用している場合は、以下で変更できます。停止時にも同じポートを指定してください。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Port 8766
powershell -NoProfile -ExecutionPolicy Bypass -File .\stop.ps1 -Port 8766
```

保存先も変えた場合、停止時に同じ `-DataDir` を指定してください。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Port 8766 -DataDir .\my-radio-data
powershell -NoProfile -ExecutionPolicy Bypass -File .\stop.ps1 -Port 8766 -DataDir .\my-radio-data
```

ターミナルから直接起動することもできます。セットアップで取得したPythonを使う場合は以下です。既定では認証済みの画面を自動で開き、停止は `Ctrl+C` です。

```powershell
.\runtime\python\python.exe app.py --port 8765
```

`--no-browser` を付けて起動した場合は、別のターミナルで以下を実行して画面を開きます。

```powershell
.\runtime\python\python.exe local_auth.py --open-browser
```

## 音楽とトーク

- MP3などの対応音声を登録し、順番またはシャッフルで再生できます。ファイル形式による再生可否はブラウザの対応コーデックにも依存します。
- 配布版のフォルダ登録はパス入力を使います。「曲を追加」からブラウザのファイル選択で音楽を登録することもできます。
- 音楽の再生中に次のトークを準備し、曲の終了後に読み上げます。
- トークはニュース、天気、曲紹介、雑談から選びます。初期設定は雑談多めで、抽選の重みを天気10・ニュース20・曲紹介15・雑談55にしています。話題の重複を抑えるため、実際の登場回数がこの比率に一致するわけではありません。
- ローカルLLMは自由な雑談だけに使います。ニュースと天気は取得した実データ、曲紹介は登録された曲名・メモ・タグを定型文に埋め込みます。長さと話し方の設定はLLMの雑談台本に使います。
- 「トークの長さ」はローカルLLMへ渡す文字数の目安です。実際の秒数は声や読み上げ速度に左右されます。LLMなしの定型トークとニュースの見出し紹介は固定の原稿を使うため、設定した秒数にそろえる機能はありません。
- 曲名、歌手名、雰囲気のタグ、一言メモを編集できます。曲紹介はこの登録情報を材料にします。実際の音響や歌詞を解析する機能はありません。
- 設定、曲一覧、履歴、生成した音声は `data` フォルダに保存されます。元の音楽ファイルは削除しません。

`sample_music` には動作確認用の短いWAVを2曲、各14秒収録しています。「デモ曲で試す」で登録でき、短時間で「曲→トーク→次の曲」の流れを試せます。あなたの音楽ファイルに置き換えて使えます。

## ローカルエンジンと軽量設定

`setup.cmd` は、公式配布物を次の場所へ導入します。配布ZIP・ソースZIPには、これらの大きなランタイムとモデル、利用者の設定・音楽・履歴を含めません。

| 内容 | 保存先 |
|---|---|
| 埋め込み版Python | `runtime/python` |
| VOICEVOX CPUエンジン | `runtime/voicevox/windows-cpu/run.exe` |
| Ollama | `runtime/ollama/ollama.exe` |
| ローカルLLMモデル | `runtime/models` |
| エンジンのログ・所有プロセス記録 | `runtime/logs` / `runtime/state` |

VOICEVOXはCPUの4スレッドを使い、全話者を一括ロードせず、使う音声モデルだけを読み込みます。LLMは小型の4Bモデルを採用し、Ollamaは同時に1モデル・1生成を使う設定として、KVキャッシュも軽量化します。LLMは使用後3分を目安にモデルをメモリから解放する設定です。実際のメモリ使用量と生成速度はモデルやPCに依存します。

モデルの初回読み込みが必要な場合も、音楽の再生中に次の原稿と音声を先に準備します。不要な待ち時間を減らしつつ、LLMや音声エンジンが使えない場合は定型文・ブラウザ音声へ切り替えます。

開発時の検証環境では、モデル読み込み済みのLLM生成と音声合成を合わせて約3〜6秒という実測でした。初回に約51秒、別の再読み込みでは約9秒とばらつきがあり、少数の計測による参考値です。CPUのみの環境などではさらに時間がかかる場合があります。この待ち時間を曲の再生中に吸収する設計です。

起動用の環境変数は子プロセスだけに適用します。モデルの保存先は `runtime/models`、Ollamaのクラウド機能は無効にし、接続はこのPCのループバックに限定します。Windows起動時の自動起動や、システム全体の環境変数は設定しません。すでに起動済みのサービスを再利用する場合、そのサービス自体の設定は変更しません。

エンジンだけを起動・確認する場合は以下を使えます。単独の停止操作は、ラジオが利用中なら停止を見送ります。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\runtime-control.ps1 -Action Start
powershell -NoProfile -ExecutionPolicy Bypass -File .\runtime-control.ps1 -Action Status
powershell -NoProfile -ExecutionPolicy Bypass -File .\runtime-control.ps1 -Action Stop
```

## 読み上げ

### すぐ試す場合

VOICEVOXが接続されていないときは、ブラウザの読み上げ機能を使用します。利用できる日本語の声や品質はWindowsとブラウザの環境に依存します。声が表示されない場合はWindowsの日本語の音声機能を確認し、ブラウザを再起動してください。ブラウザの音声によっては、読み上げのために通信する場合があります。

声の有無は、アプリ設定内の「ブラウザ読み上げの声」で確認してください。WindowsのAyumi、Haruka、Ichiro、Sayakaなどの日本語OneCore音声は、ブラウザが公開していれば選べます。従来のWindows Speech/SAPIの声一覧に日本語がなくても、ブラウザ側には表示される場合があります。声を選んだ後は「トークを試聴する」で確認します。

### VOICEVOXを使う場合

1. `setup.cmd` で導入後、`start.cmd` がエンジンを起動します。手動で導入する場合は[VOICEVOX公式サイト](https://voicevox.hiroshiba.jp/)から取得してください。
2. アプリの設定で接続を確認し、声を選びます。標準接続先は `http://127.0.0.1:50021` です。自動起動はこの標準接続先を対象にします。
3. 読み上げの試聴で動作を確認します。

初期設定は、落ち着いた女性の声として「冥鳴ひまり（ノーマル）」、話者ID `14`、読み上げ速度 `1.02` です。アプリの設定で変更できます。この声を使う場合のクレジットは `VOICEVOX:冥鳴ひまり` です。

VOICEVOXは無料で利用できます。音声利用時はVOICEVOXを利用した旨のクレジットを表記し、選択した音声ライブラリの規約にも従ってください。画面にはVOICEVOXのクレジットを表示します。録音・公開・再配布する場合は、公開先にも必要な表記を追加してください。[VOICEVOX利用規約](https://voicevox.hiroshiba.jp/term/)

## ローカルLLMを追加する場合

LLMを使わない状態でも、定型文によるDJトークを作れます。初回セットアップは[Ollama](https://ollama.com/)を `runtime/ollama` に導入し、日本語の雑談用に小型モデル `qwen3:4b-instruct` を取得します。モデルごとの利用条件を確認してください。

設定でローカルLLMを有効にし、接続先とモデルを選びます。標準接続先は `http://127.0.0.1:11434` です。クラウドモデルや課金APIを設定する機能はありません。ローカルLLMが利用できない場合は定型文に戻ります。

LLMは日常の小さな話題など、自由な雑談の原稿だけを作ります。天気とニュースは取得した実データ、曲紹介は登録した曲名・アーティスト・メモ・タグを定型文に埋め込み、LLMで改変しません。LLMの雑談には不自然な表現や誤りが混じる場合があります。原稿と、ニュース・天気の出典は画面で確認できます。

## ニュース・天気

- ニュースは設定したRSS/Atomフィードから取得します。初期設定はITmedia NEWSです。日本時間できょう配信され、まだ紹介していない見出しを選びます。一般ニュースなどは利用可能なフィードを追加できます。配信元の利用条件に従って使い、個人で聴く用途を想定しています。見出しを改変せず配信元とともに紹介し、記事全文の取得・朗読は行いません。[ITmedia公式RSS一覧](https://corp.itmedia.co.jp/media/rss_list/)、[コンテンツ利用について](https://corp.itmedia.co.jp/media/image/)
- ニュースを追加する場合は、利用を認められた公開HTTPSのフィードURLを登録してください。情報取得にはインターネット接続が必要です。
- 天気は[Open-Meteo](https://open-meteo.com/)から取得します。地域名と緯度・経度を設定します。[無料APIの条件](https://open-meteo.com/en/terms)は非商用利用、呼び出し上限、出典表示などです。
- 取得できない場合に、古い情報を新しい情報として紹介しないようにします。最新情報を必要としない曲紹介や雑談へ切り替えられます。

## YouTube連携（試験機能）

YouTubeは公式の埋め込みプレーヤーで再生します。公開・限定公開の再生リストや動画を対象とし、非公開リストへのログイン機能はありません。

プレーヤーを表示した状態で利用してください。広告の除去、音声だけの取り出し、ダウンロード、非表示での再生を提供する機能はありません。動画の埋め込み禁止、地域制限、自動再生制限、YouTube側の変更などで再生できない場合があります。安定して作業中に聴き続ける用途には、手持ちのMP3が向いています。[公式プレーヤー資料](https://developers.google.com/youtube/iframe_api_reference)、[開発者ポリシー](https://developers.google.com/youtube/terms/developer-policies)

## 保存データと接続

本アプリのHTTPサーバーは `127.0.0.1` にだけ公開し、LANやインターネット向けには公開しません。VOICEVOXとOllamaの接続先もループバックに限定します。ニュースと天気、YouTubeを利用するときは各配信元への通信が発生します。

v0.2.2は、サーバーの起動ごとに32バイトの秘密トークンを生成し、公開のヘルスチェックと画面ファイルを除くAPIに認証を適用する構成です。Windowsでは `data/session-<ポート番号>.json` を同じWindows利用者だけが復号できるDPAPI形式で保存します。ブラウザは起動URLのfragmentから受け取った認証情報をURLから除去し、そのオリジン・ポートの `sessionStorage` に保持します。

音声の再生には、認証済みAPIが発行するパス限定・有効期間12時間の署名URLを使います。音声URLへBearerトークンそのものを載せず、Cookieも使いません。`local_auth.py` はブラウザ起動と終了操作の認証を担当するため、配布物の一部だけを差し替えず、アプリのファイル一式を更新してください。

この認証は、信頼できない別のローカル利用者・プログラムからのAPI操作を制限するためのものです。Windows管理者や、同じ利用者の権限で動くマルウェアからの保護まではできません。

`data` フォルダには曲名、登録したファイルパス、履歴、設定などを保存します。ファイル選択でアップロードした音楽はこのフォルダ内にコピーします。生成音声も保存します。配布物には作成者の `data` フォルダを含めていません。共有する場合も、自分の `data` フォルダを含めないでください。

起動スクリプトのラジオ本体のログは `data/server-stdout.log` と `data/server-stderr.log` に、各エンジンのログは `runtime/logs` に保存します。ラジオが起動しない場合は前者、VOICEVOXやOllamaが接続されない場合は後者を確認してください。

## 開発・検証

実施した確認と今回の対象外は [検証記録](VERIFICATION.md) にまとめています。

```powershell
python -m unittest discover -s tests -v
```

ローカルHTTPのファイル配信・Range処理、入力検証、情報処理などを自動テストしています。v0.2.2の単体テスト81件、隔離したEdgeの統合テスト21項目、起動・停止ランチャーの5ケースが成功しました。新しいブラウザ試験では認証・署名付き音声・設定保存・CSP違反がないことを確認しましたが、公式YouTube iframeの実互換性はこの21項目には含めていません。別の隔離Edge試験で公式サンプル動画の表示・再生時間の進行を確認し、CSP違反と外部リクエストへの認証情報の漏出はありませんでした。コミット後の最終ZAPと配布ファイルの検証は別途実施・記録します。

v0.2.0/v0.2.1では、起動・停止スクリプトを検証用ポートで確認しました。またWindows版Edgeで、日本語のブラウザ音声を使った「曲→トーク→次の曲」、一時停止・再開、停止後に古いトークが割り込まないこと、モバイル幅での表示など19項目を確認しました。これは過去の版の結果です。

VOICEVOXとOllamaの接続処理は模擬応答で検証し、開発時のPCでも実エンジンで原稿の生成と音声合成を確認しました。長時間の連続再生、すべての音楽コーデック、すべてのYouTube動画・再生リスト、外部サービスの常時利用は未検証です。

Python標準ライブラリのみで実装しているため、`pip install` は不要です。費用は既存PCと個人利用の範囲を想定し、電気代・通信費を除きます。将来のサービス条件変更については配信元の案内を確認してください。
